## 3. 兩邊一致的結論

- 整合方式：SEQ 新增分頁，裡面放 iframe，載入由 SEQ 進程在背景開的本機 HTTP server。Viewer 前端畫圖、i18n、PNG／HTML 報告邏輯保留。
- 不走 `js_api` 傳資料（二進位過 JSON 橋會很慢）。pywebview 6.2.1 其實支援自訂 server class／WSGI app，但仍選獨立 server（理由見 §6）。
- server 改綁 `127.0.0.1` 隨機埠，每次啟動產生 token；驗證 Host 與 token；只送白名單靜態檔。
- 語言以 SEQ 為準。偏好（主題、折疊）不再靠 `localStorage`（隨機埠會讓它每次遺失），改存 `analysis` 自己的 `analysis_prefs.json`（不碰 SEQ config，見 §5）。
- 下載統一改成「原生另存對話框 ＋ Python 寫檔」，不靠 `a.download`（pywebview 預設 `ALLOW_DOWNLOADS=False`）。存檔路徑只接受剛由對話框核發的值。
- 開檔改走原生開檔對話框拿**路徑**，由 server 直接 mmap 讀，不再把整個檔案 POST 上去（現況 `rfile.read(length)` 會整檔進記憶體）。V／I 直接寫入 `open_memmap`，sha1 分塊算。
- 快取搬到使用者可寫目錄：Windows `%LOCALAPPDATA%\N6705C-SEQ\...`、macOS `~/Library/Caches/N6705C-SEQ/...`。先寫 `.tmp` 再原子 rename；開機清殘留；設容量上限與 LRU 清理；寫入權限不足時明確報錯；另需同 digest 併發建置鎖、使用中引用計數、Windows 關閉映射後才發布／淘汰、來源檔變動偵測。
- 後端只用 stdlib `ThreadingHTTPServer` ＋ numpy（numpy 已是 SEQ 相依，不新增套件）。
- 套件放 `src/n6705c_seq/analysis/`。

## 5. 互斥界線（使用者的硬性要求）

**狀態**：Python 端單一擁有者，`idle | power | analysis | draining | closing | fault`。語意在 T0 定死，施工時不得再改：

| 狀態 | 意義 | 進入 | 離開 |
|---|---|---|---|
| `idle` | 都沒在做 | 啟動；`power` 收尾完；`draining` 完成 | → `power`（`_reserve("power")`）、→ `analysis`（`analysis_enter`）、→ `closing`（關窗） |
| `power` | 任何會對儀器發命令的工作（含收尾關輸出、關連線） | `_reserve("power")` 成功 | → `idle`（工作與收尾全部結束）、→ `fault`（收尾逾時）。**關窗沿用現況：`power` 中拒絕關窗**（`webgui.py` 的 busy 檢查），所以 `power` 不直接進 `closing` |
| `analysis` | 分析分頁啟用中（從切進來起一直持有，**暫定**，見 §9-1） | `analysis_enter()` 成功，**世代編號 +1** | → `draining`（`analysis_leave`）、→ `closing`（關窗） |
| `draining` | 正在離開分析：拒絕新請求與新電源工作，等進行中工作停止 | `leave` 開始 | 工作全停、memmap 關閉 → `idle`；**若期間收到關窗，記下 `close_pending`，完成後轉 `closing` 而不是 `idle`**；超過 T0 定的收尾秒數（建議 30 秒，由 `gate.py` 的監看計時）→ `fault` |
| `closing` | 關窗收尾，拒絕一切 | `idle`／`analysis`／`draining`（含 `close_pending`）／`fault` 收到關窗 | 結束（進程退出）。**終態：任何遲到的收尾、`_release`、`leave` 都不得把它改回 `idle`** |
| `fault` | 儀器執行緒或分析工作卡住、無法確認已安全：**禁止新電源工作、禁止進分析**，不得因逾時自動釋放 | `power` 收尾逾時，或 `draining` 逾時 | → `closing`（使用者關窗）。其他出口只有重開程式 |

**收尾與退出（補）**：
- `["busy", bool]` 事件永遠等於 `App.busy` 的定義（`power`／`draining`／`closing`／`fault` 為 true，`idle`／`analysis` 為 false）；與 `state` 事件衝突時以 `state` 為準。
- 計時：`power` 收尾逾時指「工作已發出停止／結束訊號後」到 worker 回報完成的時間（不是整段工作時長，List／SEQ 本來就可能跑很久），從「`_release` 開始等待 worker」起算、`draining` 從 `leave` 開始起算、`closing` 從背景清理開始起算；秒數都由 T0 定。
- `fault` 時**不強制關 memmap**（工作可能還在用，強關會當機）：先停止接單、通知取消，能停就照常關；停不了就留著，由進程退出時作業系統回收。
- `closing` 背景清理逾時：不再等，直接 server shutdown 後 `os._exit`。第一次關窗回 False 之後，背景清理完成會呼叫 `destroy`，它在 Windows 會再觸發一次 `closing` 事件；此時狀態已是 `closing` 且清理完成，handler **回 True**（放行），不會永遠關不掉。`analysis→closing` 遇到分析工作卡住，同樣套用上述逾時後直接 `os._exit`；`draining` 帶 `close_pending` 逾時進 `fault` 後，**自動接續 `fault→closing`**。

狀態轉移一律用 compare-and-set（帶世代）：只有「目前狀態與世代都符合」才轉移，所以遲到的清理不會蓋掉 `closing` 或 `fault`。

**規則**
- 唯一取資格點是 `_reserve(kind)` 本身（不逐一列入口，日後新增的入口自動受管）。目前會走到它的公開入口：`seq_run`、`test_connection`、`all_off`（都經 `_seq_start`）與 `list_run`；`_test`、`_off_work` 只是 worker，只呼叫 `_release`。
- **T2↔T6 介面由 T0 寫死**：`_reserve(kind) -> token | None`、`_release(token)`；`poll` 事件保留 `["busy", bool]`（相容）並新增 `["state", {"state": ..., "gen": n}]`；前端 `App.busy` 維持現況語意＝「有電源工作在跑（`power`／`draining`／`closing`／`fault`）」，另加 `App.powerAllowed`＝「狀態是 `idle`」，`seq.js`／`list.js` 的啟動按鈕改看 `powerAllowed`（現況直接看 `App.busy`：`seq.js:116`、`list.js:56`、`app.js:64`，這些一併改，歸 T6）。`analysis` 狀態下 `busy=false`、`powerAllowed=false`，所以按鈕仍反灰；`analysis_enter/leave/open_path/save_path` 的簽名與回傳值（`{ok, error?, gen?}`）都寫在契約。
- 「檢查資格＋登記工作」與 `leave`／`closing` 在**同一把鎖內原子完成**。每筆分析請求帶**世代編號**，舊請求、舊 `leave`、遲到的對話框回傳都不得影響新一代工作。token 要驗擁有者與世代，舊執行緒 `finally` 不能誤釋放新工作。
- 現況 `_reserve` 在**確認對話框之前**就持有資格（`web_seq.py`、`web_list.py`）。對話框開著時切到分析頁必須被拒絕，前端退回原分頁。
- **在 Python 端強制，不靠前端灰按鈕**：分析 server 每個請求（靜態檔除外）先問仲裁器——不是 `analysis` 回 423、token 不符回 403、Host 不是 `127.0.0.1` 回 403。
- 所有長工作（解析、LOD、統計、分桶、CSV、存檔）必須可取消、定期檢查取消旗標。卡住時**不得因逾時釋鎖**。
- 切離分析頁：停止接單 → 取消進行中請求 → 等工作停止 → 關閉 memmap／`_open_cache`／NpzFile → 才回 `idle`。
- 關視窗：`events.closing` 處理函式**不可同步等待**（會卡 UI）；先回 False，背景清理完成後再 `destroy`。server shutdown、關 memmap 必須在 `os._exit` 之前。所有 destroy／退出路徑都要清理，不只關窗事件。
- 當掉：鎖只在記憶體。**同進程分析當掉會讓整個 GUI 一起消失**，儀器輸出可能停在開著的狀態——但此時互斥已保證沒有排程中的電源工作，風險限於「使用者需手動關輸出」，報告與 UI 說明要寫明。

**模組邊界**
- `analysis/*` 只准 import stdlib、numpy 與 `analysis` 自己；**禁止** `n6705c.*`、`pyvisa`、`usb`、`webview`、`webgui`、`web_seq`、`web_list`、`execute`、`e36441a`、`form`。注意 `src/n6705c/core/dlog.py` 是儀器端 DLOG，名稱相近，不要混用。
- `webgui` 只 import `analysis.server`、`analysis.gate` 與 `analysis.contracts`（flag 與介面常數，純常數模組）；需要給 analysis 的能力（開檔／存檔對話框、語言）以窄介面（callback）注入。
- 加兩個測試：AST 掃 import；子進程 import analysis 後斷言 `pyvisa` 不在 `sys.modules`。
- `analysis/__init__.py` 由 T0 建立（空檔），讓第 2 波 T1／T2 建檔時套件已存在。

**偏好存放（定案）**：`analysis` 自己的版本化 JSON（`analysis_prefs.json`，放使用者設定目錄、原子寫入），**不碰** SEQ 的 `config`（`form.load_config/save_config` 只認 resources／demo／lang 三個鍵，每次存檔會整檔重寫、丟掉別的區段）。語言由外殼以 query／`postMessage` 傳入。

**保證範圍（待使用者決定，見 §9-4）**：預設只保證**同一個 GUI 進程內**互斥。CLI 與第二個 GUI 是另一個進程，自己的鎖互不相見；若要涵蓋，需加 OS 檔案鎖並讓 CLI 入口取得同一把鎖——此時 `cli.py`（`cli.py:126,143`）與 CLI 測試**歸 T2**。

**Feature flag（單一來源）**：`ANALYSIS_ENABLED` 只定義在 Python（`analysis/contracts.py`），由 `config()` 下發，JS 只讀、不自己定義（作用類似 `LIST_VERIFIED`，但定義在 Python；`tests/test_webgui.py:90` 斷言 `config()` 只有三個鍵，T2 要同步改）。關閉時：分析分頁不顯示、`analysis_enter` 一律拒絕、analysis server 不啟動；**但仲裁器的安全行為（`fault`、非同步 `closing`、世代檢查）照常運作**。所以「關閉＝現況」只指畫面與功能，不是指內部狀態機退回舊 `_busy`。

## 10. 風險與還沒驗證的事

- 沒有任何實測；記憶體、耗時數字都是舊交接文件的環境紀錄，不是保證。
- Windows：防火牆對 `127.0.0.1` 是否跳詢問、WebView2 iframe 行為、非 ASCII 路徑、唯讀安裝目錄，都要實機驗。
- 子進程隔離只擋 GIL 與當機，**擋不住實體 RAM 與磁碟頻寬**。
- 電源控制路徑目前仍有未實機驗證的部分（見 `HANDOFF.md`），互斥改動會碰到這些入口，需要迴歸測試。
- 同進程分析當掉會讓整個 GUI 消失，儀器輸出可能停在開著的狀態（§5）。

## 11. 回滾與遷移

- **回滾**：`ANALYSIS_ENABLED`（作用類似 `LIST_VERIFIED`，但定義在 Python）預設關閉分頁；關閉時畫面與功能等同現況（仲裁器的 `fault`／非同步 `closing` 安全行為仍在，見 §5），既有功能不受影響。驗收通過才打開。
- **不遷移**：舊 Viewer 的 `server/.cache` 與瀏覽器 `localStorage` 偏好都不搬，首次使用重建、偏好用預設值。
- **文件**：完成後由 T7 更新 `README.md`，`HANDOFF.md` §11 改寫成實作狀態。
