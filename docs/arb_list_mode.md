# ARB List 模式　討論紀錄

> ⛔ **使用者明確說「開工」之前，不准修改任何程式碼**（`src/`、`tests/`、`packaging/` 等）。
> 本文件只記錄設計討論；任何實作都要等使用者開口。

更新：2026-10-13　狀態：**討論中，未開工**

## 1. 目標

每個通道可以輸出一串不同設定的波形（段落），每段參數各自獨立，設定完可以排列順序。

## 2. 已定案

| 項目 | 決定 |
|---|---|
| 排序範圍 | **單一通道內**的段落順序（不是跨通道的總清單） |
| 與上電時序表的關係 | **並存**：GUI 另開「List 模式」分頁，原 CSV 時序表不動 |
| 輸出模式 | **CDW（Constant Dwell）**：每通道把整串段落在電腦端合成一條點陣列，下載成一個 `ConstantDwellArb` |
| 點數 | 每通道最多 65,535 點 |
| 段落輸入 | 每段填**時間與波形參數**，點數由程式算（`點數 = 時間 / dwell`），不讓使用者直接指定每段點數 |
| dwell | **所有通道共用一個 dwell**；預設自動選，可手動覆寫 |
| 整串重複 | **全部通道一起重複**（整段時序重做 n 次）：每通道用最後電壓補到共同週期 P，延遲包在每一輪內，用 `ARB:COUNT n`（≤ 256），不耗點。見 §2.5 |
| 段落不連續 | 允許，只警告不阻擋（14585A 也是如此） |
| 預覽 | 仿 14585A：上方各通道泳道、共用時間軸，點選泳道切換編輯的通道 |

### 2.1 為什麼不用 ARB Sequence

- Sequence 是儀器真的認得段落的模式，但整條共用 **511 點**；曲線段越多，`ARB:SEQ:QUAL?` 從 100 降到 16，波形變粗。
- CDW 有 65,535 點，但儀器只看到「一串電壓值 + 一個 dwell」，不知道段落存在。段落只存在於電腦端的介面。

### 2.2 為什麼不讓使用者決定每段點數（與 Codex 討論的結論）

- CDW **整串只有一個 dwell**，所以每段的點數和時間綁在一起：`段落時間 = 點數 × dwell`。
- 兩段相同時間、不同點數，需要不同的取樣間隔，CDW 做不到。只能全部用最細的 dwell，再把粗的那段用重複點補滿，**不會省到點**。
- 每段各自取樣間隔是 UDEF 的能力，但 UDEF 只有 511 點。
- 例外：曲線的「控制點」（例如自訂曲線用 20 點描述）可以跟時間無關，程式再插值成等間隔的點。以後要做進階輸入時，點數欄位要跟時間連動。

### 2.3 dwell 自動選取規則（草案）

1. 塞得進預算：`dwell ≥ P / 65,535`（P＝共同週期＝各通道「延遲＋段落（含每段 Repeat 展開）」的最大值；整串重複不展開）
2. Sinusoid／Triangle 每週期至少 N 點（暫定 20）
3. 最快的 rise／fall 至少 N 點（暫定 10）

- 取最嚴格的條件，取整到 10.24 µs 的倍數，範圍 10.24 µs～0.3 s。
- 條件 1 和條件 2、3 衝突時，以條件 1（塞得進）為優先，並警告哪一段會變粗。
- 手動覆寫後總點數超過 65,535 時，**擋下不能執行**。

### 2.4 介面要即時顯示

- 每段點數、取整後的實際時間與誤差
- 總點數預算條（例：`42,310 / 65,535`）；補齊到 P 後每通道點數都等於 `P / dwell`，所以是一條全域的預算條。各通道的延遲與補齊佔用的點數另外標出
- 實際輸出的階梯預覽（每點維持一個 dwell），不是理想曲線

### 2.5 整串重複：為什麼選「全部通道一起重複」（2026-10-13 使用者定案）

- 儀器沒有 `TRIG:TRAN:DEL`，通道延遲只能做成點陣列前面的平線；CDW 也不能當 Sequence 的一步（p.316），`delay.py` 的「延遲步＋n 個波形步」用不了。
- 若每通道各自重複：延遲只能出現一次，只能全部展開成點（很吃預算）；段落長度不同的通道每輪越錯越開。
- 全部通道一起重複：每通道補到同一週期 P，延遲包在每輪內，每輪時序相同、不漂移；直接 `ARB:COUNT n`，n＝1 就是一般情況，只有一條程式路徑。
- 條件：所有通道共用一個 dwell，P 才會是 dwell 的整數倍。dwell 因此由最長的通道決定。
- 與 14585A 的差異：14585A 的 Sequence Repeat 在每個通道底下；這裡是全域一個設定。
- 每段各自的 Repeat Count（§5 第 2 項）仍展開成點，跟整串重複無關。
- 超過 256 輪：要由電腦端重新 `INIT` 迴圈，每輪之間有毫秒級空隙（單通道 arm 實測間隔約 13–22 ms）。第一版不做。

## 3. CDW 的代價與風險

- **段落邊界會對齊 dwell 的整數倍**，時間不會剛好等於設定值。
- **曲線實際上是細階梯**，dwell 越小越接近理想曲線。
- **通道延遲與補齊也耗點**：例如 dwell 102.4 µs 時，延遲 2 s 約佔 19,500 點；較短的通道補到 P 也一樣。
- **改任何一段都要重新下載整串**；前面板只看得到一條 CDW。
- **COUNT 上限 256**：整串重複最多 256 輪；每段的 Repeat Count 只能展開成點。
- **同一通道的電壓與電流 CDW 共用設定**，設定其中一種會重置另一種。
- **傳輸**：目前 core 用 ASCII 下載，65k 點約 600 KB 文字，時間要實測；儀器也支援二進位區塊，但要處理位元組序。
- **合成規則要另外定義**：`ArbWaveform.points()` 是給預覽用的（Step 會多畫一段尾巴），不能直接拿來當輸出點。每段的端點、接縫與結束保持電壓要另外定義。
- **實機未驗證**：CDW 本身；`COUNT > 1` 時輪與輪的接縫有沒有空隙；跑滿 256 輪後各通道是否仍對齊。都還沒接實機量過。

## 4. 參考：Keysight 14585A 介面（2026-10-13 使用者提供截圖）

```
┌───────────────────────────────────────────────────────┐
│ 各通道泳道，共用時間軸 (V1/V2/V3/V4)，選取者紅框        │
├───────────────────────────────────────────────────────┤
│ 段落縮圖列 ◀◀ ◀ [▭][∿][⌐] ▶ ▶▶                       │
│ Move Left｜Add｜Modify｜Delete｜Move Right              │
│ Component / Sequence Stats（段落時間、總時間、段落數）    │
│ Sequence Repeat：Continuous / Count                    │
├──────────────┬──────────────────┬─────────────────────┤
│ 波形圖示選單   │ 參數表單（單位）    │ 參數示意圖（標註箭頭）  │
└──────────────┴──────────────────┴─────────────────────┘
```

14585A 各波形的參數（CDW 由我們自己算點，所以段落參數**不必遷就** core 的 dataclass，可以照這個定義）：

| 波形 | 參數 |
|---|---|
| Step | Start／End Amplitude、Delay、End Time |
| Ramp | Start／End Amplitude、Delay、Ramp Time、End Time |
| Trapezoid | Amplitude、Offset、Start／Up／High／Down／End Time |
| Sine | Amplitude、Offset、Frequency、Phase |
| Triangle | Amplitude、Offset、Frequency、Phase |
| 每一段共有 | Repeat Count |

- Phase 與 Triangle 在 Sequence 模式下儀器做不到；用 CDW 只要算點就能做到。Square、Gaussian、Sinc、Swept 也是同樣的情況。
- 截圖中段落電壓不連續（Ramp 結束在 2 V，接著 Sine、Staircase 從其他位置開始），14585A 不會阻擋。

### 5.1 建議（Claude，2026-10-13，**待使用者確認**）

| # | 建議 | 理由 |
|---|---|---|
| 1 | Triangle、Phase **都加** | CDW 每點自己算，多一種波形只是多一條公式 |
| 2 | Repeat Count **放進第一版** | 展開成點只是重複 n 次；代價是點數，預算條已會顯示 |
| 3 | **不做 Continuous，只做 Count** | core 已支援 `INF`（`core/arb/scpi.py`），難在 GUI：「■ 全部關閉」執行中是停用的，`run_plan` 要跑完才返回，Continuous 需要另做執行中可中斷的流程 |
| 4 | **只畫曲線** | 箭頭標註每種波形都要各寫一套 canvas 程式碼；表單欄位名稱已能說明參數 |
| 5 | **可以** | 照現有「維持高點 DC」勾選框（預設不勾）＋「■ 全部關閉」的做法；core 已有 `ARB:TERM:LAST` |
| 6 | **不做 CLI** | CSV 已有 `n6705c-seq check/run`；合成邏輯用一個測試檔驗證即可，批次執行有需要再加 |
| 7 | **N＝20／10 可以，但 dwell 規則要改**（見下） | |

**第 3 項連帶：整串重複的做法** — 已定案，見 §2.5（全部通道一起重複，`ARB:COUNT n`）。

- 連帶影響：延遲包在每輪內，儀器端 Continuous（`ARB:COUNT INF`）已沒有延遲的矛盾；第 3 項剩下的只是 GUI 的「執行中可中斷」。

**第 7 項：dwell 規則修改**

- §2.3 的條件方向不同：條件 1 是 dwell 下限，條件 2、3 是上限，「取最嚴格」得到的是範圍不是單一值。
- 建議自動 dwell ＝**塞得進預算的最小值**：`max(10.24 µs, 總時間 / 65,535)`，取整到 10.24 µs 倍數。波形最細，規則只剩一條。
- N 改為**只用來判斷警告**（例：某段 Sine 每週期不到 20 點就警告）。
- 代價：點數用最多、傳輸最久。若實測 ASCII 傳 65k 點太慢，改成「符合 N 的前提下取最大 dwell」來省點。**要等傳輸時間量完才定案。**

**第 7 項：Sine 頻率上限**

| 限制 | 上限 | 依據 |
|---|---|---|
| 取樣（每週期 20 點） | 約 4.88 kHz | `1 / (20 × 10.24 µs)` |
| 取樣（每週期 10 點） | 約 9.77 kHz | 接近儀器內建 Sine 上限 10 kHz（`FREQUENCY_MAX`） |
| **N6762A 輸出反應** | **未知** | 真正的上限，要實測 |

- N6762A 是精密型模組，重點在低雜訊不在速度；`supports_bandwidth` 只對 SMU（N678xA）成立，無法調高迴路頻寬。
- 查不到 N6762A 的 10%→90% programming time。`docs/hw_smoke_capture.png` 只有 20 ms 斜坡，看不出頻寬。
- 負載與振幅也有影響：輕載／空載時下降段只能靠輸出電容放電，Sine 下半週先變形；振幅越大需要的斜率（`2πfA`）越大，越早碰到 slew 極限。
- **不寫死頻率上限，分兩層：**
  1. **擋下**：每週期少於 10 點（超過約 9.7 kHz），取樣硬限制。
  2. **警告**：每週期少於 20 點（超過約 4.9 kHz），或超過實測的模組頻寬。頻寬做成依模組型號查表的常數，換模組或負載時可調。
- Triangle 的尖角含高次諧波，同頻率下比 Sine 更早被磨圓，警告門檻要比 Sine 低。
- **實測方式（開工後）**：用現有數位化器擷取，在實際負載下輸出振幅 1 V、offset 2 V 的 Sine，頻率 10、30、100、300、1k、3k Hz，找振幅掉到 -3 dB 的頻率。數位化器 40.96 µs/pt 大約只看得到 3 kHz；推測 N6762A 頻寬比這低，待實機確認。
